# 45 · 开档仪式 —— 让这件作品开始记得

> 2026-09-14。`docs/43` 裁完了存档该记什么、不记什么；`docs/43 §8` 建好了它。
> 这一页只回答最后一个问题：**谁、在什么时候、做哪几件事，它才真的开始记。**
>
> 写成仪式而不是写成配置说明，是因为它**不是一次配置**。
> 它是这件作品从「今天来过的人明天就不存在了」变成「来过的人留在这儿」的那一刻，
> 而那一刻应该有人在场、应该被验一次、应该知道自己刚才做了什么。

---

## 0 · 两副身体，两套仪式

这件作品有两处会被人站上去：**装置那台机器**，和**网站**。
它们的存档是分开的，而且**难易完全不同**：

| | 在哪 | 需要什么 | 谁能做 | 今天能不能做 |
|---|---|---|---|---|
| **甲 · 装置** | 现场那台电脑的硬盘 | **什么都不需要** | 开机的人 | **能** |
| **乙 · 网站** | Vercel 上的一个键值库 | 一个有 Vercel 权限的人 | 只有他 | 等他 |

**先做甲。** 理由不是"甲比较容易"，是**甲才是这件作品真正发生的地方** ——
观众是站在装置前面的，网站是他事后或事前看的。
乙没做之前，网站上的存档**不存在**（端点 404），
`/lineage` 说它那句早就准备好的话，`/about` 那一句「每一次到访只留下一行」
根本不会印出来 —— 页面不会因此说假话，这一点已经有测试钉着（`privacy-truth.test.ts`）。

**所以乙晚一点做，什么都不会坏。** 只是网站还没开始记得而已。

## 甲 · 装置那台机器（今天就能做，不需要任何账号）

### 要做的

```bash
npm run kiosk
```

**就这一条。** 不用设环境变量、不用注册、不用联网。

`kiosk` 现在默认把档案写到 `archive/visits.jsonl`（仓库根目录下）。
要换地方就自己给 `ARCHIVE_FILE`：

```bash
ARCHIVE_FILE=/Volumes/展览U盘/visits.jsonl npm run kiosk
```

### 回执：怎么知道它真的在记

**这一步不许跳过。** 这条回路最坏的坏法是"看上去在跑，其实一行都没写下来" ——
画面照常、观众照常，只有档案是空的，而没有人会发现，因为没有人会去看那个文件。

自己站到画面里走完一次，然后：

```bash
npm run archive:read
```

它会打印到访次数、文件在哪、最近五条长什么样。看到数字从 0 变成 1，仪式才算成。

```
2 次到访 / visits
  /Users/…/archive/visits.jsonl
  {"n":1,"species":"porcelain","at":"2026-09-14"}
  {"n":2,"species":"patrol","at":"2026-09-14"}
```

### 一行长什么样，以及为什么就长这样

```json
{"n":1,"species":"porcelain","at":"2026-09-14"}
```

**46 字节**（实测，不是估的）。三个字段，一个都不能多：

- `n` —— 第几位。**服务端自己发的号**，客户端送什么号都不算数。
- `species` —— 他选了哪个物种。闭集，不在名单里的直接拒。
- `at` —— 粗到**天**。不是时刻。

**没有 IP、没有影像、没有动作、没有姓名、没有账号、没有 User-Agent。**
这不是客气，是 `docs/43 §9.4` 那条「永久保留」裁定的**唯一支点**：
那条裁定不是靠匿名化站住的，是靠**那一行里根本没有个人数据**站住的。

实测过一次：把 `ip` / `email` / `ua` / 一个伪造的 `n` 一起塞进请求体，
落到盘上的仍然是上面那三个字段，伪造的号被忽略、其余被丢掉。
（`packages/app/test/archive.test.ts` 钉着这件事，改一个字段名就红。）

### 收摊的时候

`archive/visits.jsonl` 是**只追加**的普通文本。拷走就是备份，
`docs/43` 的裁定是**永久保留**、只增不减 —— 所以别删，也别"整理"。

## 乙 · 网站（等一个有 Vercel 权限的人）

### 他要做的

```bash
vercel link                       # 如果还没连上这个项目
vercel integration add upstash    # 会开一个浏览器页面，在那儿建库
vercel --prod                     # 函数只在重新部署之后才读得到新变量
```

或者不用命令行：项目 → Storage → Browse Marketplace → Upstash for Redis → Create。

**环境变量不用手打**，集成自己注进去。代码两套名字都认
（`KV_REST_API_URL`/`KV_REST_API_TOKEN` 和 `UPSTASH_REDIS_REST_URL`/`UPSTASH_REDIS_REST_TOKEN`），
所以"装哪一家"这个决定不用回到代码里改。

### 为什么是这一家

`INCR` 一条命令就给出 `n` 要的那个**原子序号**（`docs/43 §4.2`）；
它有 HTTP 端点，所以一个依赖都不用装；
而这一页是**几天才被打开一次**的，Neon 那种五分钟冷启动在这里是纯亏。
选型是当天在 `vercel integration discover --category storage` 上现查的，
不是抄 `docs/43` 里那份调研快照 —— 那份快照会过期。

### 回执

```bash
curl -s https://useeme.ptoq.io/api/visits
```

- 还没装：`{"ok":false,"code":"DISABLED"}`（404）—— **这是正常的，不是坏了**。
- 装好了：`{"ok":true,"total":…,"entries":[…]}`。

然后打开 `/about`：那一句「每一次到访只在服务端留下一行」
**会自己出现** —— 它是先问 `/api/visits` 再决定印不印的，不用改代码、不用有人记得。
这就是为什么乙可以晚一点做：页面在那之前不会说一句假话。

### 那一步没做之前，线上是什么样

| 地方 | 样子 |
|---|---|
| `/api/visit` `/api/visits` | 404 + 结构化 JSON，不是崩溃 |
| `/lineage` | 说它那句「这条回路在这个版本里不存在」 |
| `/about` 的隐私段 | **少一句**。不会有「存档暂未开启」这种占位话 —— 观众不需要知道我们的部署顺序 |
| 装置 | 照记不误。甲和乙互不依赖 |

## 丙 · 这个仪式为什么值得是一个仪式

`docs/43` 花了九百行论证该记什么。全部的结论压成一句话是：
**记下来的东西必须少到不伤人，又必须真的记下来。**

前半句是设计，已经做完了 —— 三个字段、46 字节、测试钉着。
**后半句是一个动作，而动作会被忘记。**

而它被忘记的时候没有任何征兆：端点 404 是静的，档案文件不存在是静的，
`/about` 少一句话是静的。这件作品会继续正常运行、继续好看、
继续每天接待人 —— 只是不记得任何一个。

所以它需要一个有回执的仪式：`npm run archive:read` 打出那个从 0 变成 1 的数字，
或者 `curl` 打出那个 `"ok":true`。**看见那个数字之前，这件事就还没做完。**
