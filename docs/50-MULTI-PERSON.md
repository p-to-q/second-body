# 50 · 多人入镜 —— 两个人、三个人，每人一具身体

> 2026-09-14。作品负责人："两个人、三个人……如果模型支持，两个、三个甚至更多人入镜都可以，但也可以之后硬限制人数避免复杂。
> 我觉得支持两三个人就行。从我们的 CV 往回推，单独作为一条线。每一个入镜的人生成一个对应的机器人。"
>
> 这一页先定设计（§0–§7），再记落地（§8–§10）。标记：**[实测]** = 本机跑出来的数，写了命令；**[推断]** = 从文档或源码推的，没跑过。
> 数值的唯一来源是 `packages/core/src/tuning.ts` 的 `PEOPLE` 块。

```
Outcome:    两三个人同时站到摄像头前，每个人各有一具跟着自己动的身体；一个人走开，其余的人不受影响。
Boundary:   capture（numPoses、worker 消息）→ core/people.ts（身份、谁拿到身体、站位）→ creature（共用桶的伴随身体）→ main.ts 接线；
            控件表一项、HUD 一行、一个工作台页。弧线、忒修斯、存档、读数的**逻辑**一行不改。
Invariants: `?people=1` 是这一版之前的那条路，逐字相同（numPoses=1、没有 others、没有伴随身体）；
            draw ≤ 40、tris ≤ 250k 在任何人数下成立；帧循环里不 throw；存档仍是一场一行。
Proof:      `npm run check`、`npm run build`；core/test/people.test.ts、app/test/people-{budget,flag}.test.ts 逐条先红后绿；
            无头 Chrome raw CDP 在 1/2/3 具身体下量帧时间与推理耗时（§10）。
Non-goals:  外观重识别（embedding）、每人一条弧线、每人一个物种、伴随身体的低面数 LOD（§8 计划）。
```

## 0 · 结论先说

1. **CV 撑得住三个人，但代价不是线性的那一种。** `numPoses > 1` 时 MediaPipe 在"跟踪到的人数 < numPoses"的每一帧都重跑检测器
   （§1.2）——**画面里只有一个人、却开着三人档，是最贵的那一种**。所以人数上限不是越大越好，默认值由实测定（§1.5）。
2. **身份是我们自己跟出来的**：躯干中心的预测位置 + 尺度 + 姿态描述子，门限挡掉不可能的配对，在 ≤ 4×8 的矩阵上穷举最优配对。
   出生憋 0.3 秒、丢了 1 秒才死、死后 3 秒内在附近回来还是原来那个 id。没有外观特征（§2）。
3. **一条弧线，不是每人一条。** 这件作品的命题是"一个自我住进很多具身体"，而忒修斯之船是**一条**船：
   台上所有身体共用同一份正在被一件件换掉的 genome，每个人拿到的是**这具船身的一个分身**（自己的骨架、自己的站位、自己的颜色）。
   主身体（最早拿到身体的那个人）驱动弧线、读数、声音、取景；**主身体走了不归零**，交给台上已经有身体的下一个人（§3）。
4. **帧预算：两具放得下，第三具要等 LOD。** 所有身体共用同一组 `InstancedMesh` 桶（draw call 和一具时一模一样），
   差异色走 `instanceColor`。面数上，忒修斯的借件门保证一具身体最坏 125k 面 → **两具正好 250k，前提是伴随身体进场时主身体的描边让位**（§5）。
5. **默认 `?people=1`，网页和现场都是**，直到 §10 的实测说可以改（§6.3 有裁定与理由）。

## 1 · CV：从 MediaPipe 往回推

### 1.1 `numPoses` 支持到多少

`@mediapipe/tasks-vision@1.0.1` 的 `PoseLandmarkerOptions.numPoses`："The maximum number of poses can be detected"，缺省 1 [一手：`vision.d.ts`]。
没有写上限；图里检测器是 SSD 风格的 BlazePose detector，后面接每人一次关节模型。**运行中可以 `setOptions({ numPoses })` 改**，不用重新建 worker
（`capture/pose-worker.ts` 的 `options` 消息，§8）。

模型卡自己把**多人**列在 out-of-scope 里 [一手：`pose_model_card.pdf` p.3，docs/24 §1]：它能跑，但 Google 没有为多人评过精度。

### 1.2 检测器每帧跑，还是跟踪 ROI

PoseLandmarker 是 detector → 从上一帧关节推 ROI → 在 ROI 上跑 256×256 的关节模型（docs/49 §3 用法 A 那一段引过）。
多人时的门：**已跟踪的 ROI 数 < numPoses 时，这一帧重跑检测器**（pose_landmarker_graph 的 previous-loopback + gate）[推断：图的结构，没有逐行复核源码]。
两个直接后果：

- 画面里只有 1 个人、开着 `numPoses = 3`：**每一帧都跑检测器**（没跟满）。比单人档贵的不是"多两个人的关节模型"，是"每帧一次检测器"。
- 画面里正好 N 个人、`numPoses = N`：检测器几乎不跑，代价 ≈ N 次关节模型。

**[实测]** 推理耗时（worker 里 `detectForVideo` 的单次毫秒，假摄像头喂合成人形，§10 的命令）：

| numPoses ＼ 画面里的人 | 1 人 | 2 人 | 3 人 |
|---|---|---|---|
| 1 | 待测 | 待测 | 待测 |
| 2 | 待测 | 待测 | 待测 |
| 3 | 待测 | 待测 | 待测 |

### 1.3 输出顺序

`result.landmarks[i]` 的 `i` **不是身份**：检测器每次重跑时按置信度 / 位置重新排；两个人的 ROI 合并又分开之后顺序会换 [一手：google-ai-edge/mediapipe #4681，docs/24 §1]。
所以 `core/src/people.ts` 的测试**每一帧都把观测打乱**再喂（`people.test.ts` 的 `shuffle`）。

### 1.4 遮挡与交叉

- 靠太近（3.5m 处相距 ~75cm）时低置信度的那个人**直接被取消**（#4681）。交叉的那半秒里画面上通常只剩前面那个人。
- 偶尔在同一个人身上给两份几乎重合的结果 → 按"中心距 < 0.35 躯干、尺度比 < 1.25"去重，留分高的（`dedupe()`）。
- 半个人出画：肩不在画内就不作数（没有躯干中心就没有身份），轨迹进入丢失计时，回来还是他。

### 1.5 上限

- `PEOPLE.hardMax = 3`：`?people=` 认的最大值，也是 worker 里 `numPoses` 的上限。取 3 是**帧预算**决定的（§5：两具放得下，第三具要 LOD），不是 MediaPipe 决定的。
  放得更大只会让 §1.2 那个"没跟满就每帧跑检测器"更常发生，而多出来的人没有身体可给。
- 默认值见 §6.3。

## 2 · 身份：谁是谁

### 2.1 观测

一份姿态（只读 `screen`，回放录制没有 `screen` 就不作数）→

| 量 | 怎么算 | 为什么 |
|---|---|---|
| 躯干中心 `cx, cy` | 肩中点与胯中点的中点；胯不在画内时按肩宽往下估半个躯干 | 最稳的一块：手脚会出画、脸会转，躯干很少突变 |
| 尺度 `scale` | 肩中点到胯中点的距离（x 按宽高比折算）；胯不在时肩宽 × 1.45 | 离得远的人小：位置差按尺度折成"躯干长"，远近同一把尺 |
| 面积 `area` | 可信点包围盒 | "离得最近 = 最大"（docs/23 §S4「跟面积最大的那个」） |
| 描述子 `desc` | 肩肘腕胯膝十个点相对躯干中心、除以尺度 | 两个人站得很近时区分他们的唯一线索：一个举着手、一个没有 |

### 2.2 代价与配对

```
预测位置 = 上次位置 + 速度 × (丢了多久 + dt)
dPos   = |观测中心 − 预测位置| / 轨迹尺度                     （躯干长）
dScale = |ln(观测尺度 / 轨迹尺度)|
dPose  = 描述子平均点距（两边都可信的点 ≥ 3 个才算）
cost   = dPos + 1.5·dScale + 0.6·dPose
门限：dPos > 1.2 + 1.5·丢了多久  或  dScale > ln 1.6  → 不可能是同一个人
```

**为什么穷举而不是 Hungarian 或贪心。** 观测 ≤ 4、活轨迹 ≤ 8：部分配对最多 529 种，一帧几十微秒。
穷举在这个规模上是精确的全局最优，而且比 Hungarian 少一个带虚拟行列的实现要维护。贪心不行：
两个人并排时"观测 0 先抢走代价最小的轨迹"会把另一个人逼到一个错配上（`people.test.ts`「配对：穷举的是全局最优」）。
不匹配的代价 `unmatchedCost = 1`（每边一半）：一对配对比它还贵，就各自当新人 / 丢失。

**为什么没有外观。** 我们没有 embedding，也不想为了"认出你"去存一个像你的向量（docs/43 §0.2 同一条直觉）。
三个人的规模上，几何 + 速度 + 滞回够用；挺不住的情形在 §2.4 列出来，每一种有一个决定好的行为。

### 2.3 生死

| 阶段 | 规则 | 数 |
|---|---|---|
| 出生 | 新轨迹是 `tentative`，连续被看见（漏桶：看不见一帧扣两帧）`birthSeconds` 才转正、才有资格拿身体 | 0.3s |
| 误检 | 还没转正就丢了 `tentativeGrace` = 当它没来过 | 0.15s |
| 丢失 | 转正的轨迹丢了 `graceSeconds` 才死；期间预测位置照走、门限放宽 | 1.0s（= `PRESENCE.loseDelay`） |
| 墓地 | 死了的轨迹留 `reattachSeconds`；这期间在离开处 2.5 个躯干内、尺度相近地出现 = 同一个人回来了，同一个 id、直接转正 | 3.0s |
| 新人 | 墓地里认不上 = 新 id（单调递增，不复用） | — |

### 2.4 它挺不住的情形（以及决定好的行为）

| 情形 | 会发生什么 | 决定 |
|---|---|---|
| 两个一样高、一样姿态的人面对面走过，交叉那一刻同时停下再原路返回 | 速度预测会把他们各自送到对方那一侧 | 接受：id 可能对调一次。代价是两具身体的**颜色**对调（骨架各自跟着各自的人，站位由画面位置决定），不是身体跳到别人身上 |
| 两个人交叉时 MediaPipe 连续 1 秒以上只给一个人 | 被挡住的那条轨迹死、进墓地；从另一侧出现时离开处太远认不上 | 新 id：他的身体溶掉再长出来（一次进出场，不是一次闪） |
| 两个人贴身站着（拥抱） | MediaPipe 常常只给一个人 | 同上：一具身体溶掉。拥抱在画面上本来就是一个剪影 |

## 3 · 谁是"主身体"，以及单数的东西跟谁

### 3.1 一条弧线，还是每人一条

**一条。** 理由按这件作品自己的命题：

- docs/44 §0：「到第三分钟，他最初看到的那具身体，一件都不剩了 —— 而它仍然只跟着他动。」忒修斯之船是**一条**船。
  每人一条弧线 = 台上三条船各自换件，观众看到的是三个计时器，不是一次替换。
- "一个自我住进很多具身体"：第二个人走进来，他拿到的是**这条船此刻的样子**（已经换了七件的那一具）的一个分身 ——
  "你走进了一具已经被别人改写过的身体"，这正是 docs/17 血统那条线在一场之内的版本。
- 预算：共用 genome = 共用桶（§5.1）。每人一条弧线 = 每人一组桶 = draw call × N，两个人就越 40。

所以：**每个人各有一具身体（自己的骨架、站位、颜色、进出场），所有身体共用一份 genome 和一条弧线。**

### 3.2 单数的东西跟谁

| 东西 | 跟谁 | 理由 |
|---|---|---|
| 弧线 / 忒修斯的时间 | **有没有人**（任何一具身体在场） | 主身体走了、别人还在：不停表、不归零 |
| 忒修斯的 `motionBias`（换哪一件）与运动量加速 | 主身体 | "它拿走你正在用的那一部分"是一个人对一具身体的可验证机制（docs/44 §3）；三个人一起挥手，谁都验证不了 |
| 升档（tier） | 同上（运动量那一半） | — |
| 读数 | 主身体 | §6.1 |
| 左上角小屏 | 画全部人 | §6.2 |
| 取景（景别） | 单具身体时照 docs/49；**两具以上一律全景** | §4.3 |
| 声音 | 主身体 | 四层声音绑的是一条运动信号；三条叠在一起是噪声 |
| 存档 | 一场一行，不按人 | §7「隐私」 |
| 在场 / 归零 | 所有人都走了才归零 | §3.3 |
| 慢回路（抠图生成） | 不变：抠图是整幅画面，本来就不分人 | 慢回路在生产构建里不存在，这一版不动 |

### 3.3 主身体走了、别人还在

- 主身体的轨迹死了（丢 1 秒）：主身体交给**台上已经有身体、拿到身体最早**的那个人。他的身体不重建、不闪，只是从伴随身体变成主身体：
  拿回描边（如果物种有）、颜色回到原色、开始驱动读数和声音。
- 走掉的那个人的身体照常走溶解（它自己的在场状态走 `LEAVING`），**画在伴随身体的位置上**，溶完为止。
- 弧线、忒修斯、存档：什么都没发生。"有没有人"一直是真的。
- 滤波器状态（精化器、稳定器、生命力）**跟着人走**：交接时主通道换上接班那个人自己的那一套，不从零热身、不把上一个人的骨长带给他。
- 所有人都走了：和今天一样 —— 在场判定走 `LEAVING` → `ARC.resetAfter` 之后弧线归零、换种子、身体回到原件（main.ts `arcState.justReset` 那一段，一行不改）。

## 4 · 身体

### 4.1 同一个物种，每人一个分身

- **同一个物种、同一份 genome**（§3.1）。不是每人抽一具不同的：那要多一组桶（§5.1），而且把"一条船"拆成了几条。
- 差异：
  - **颜色** —— `PEOPLE.tints` 里按 `会话种子 × 轨迹 id` 挑一个近白的冷暖偏移，乘在材质上（`instanceColor`）。确定、**永远不是白色**（白 = 主身体的原色）；
    乘法只会压暗，不会跳出物种的调色板（docs/26 §H）。
  - **比例** —— 本来就是每人自己的：`assemble()` 按观测身高缩放（docs/04 §4），小孩的身体就是小的。**等身在每一具身体上成立**。
  - **描边** —— 伴随身体永远没有（§5.2）。这不只是预算：它让"哪一具在读数上、在声音里"不说一个字也读得出来。

### 4.2 站位

`core/src/people.ts` 的 `lineup()`：

1. 画面里偏离中线 `(cx − 0.5)·宽高比` 个画面高度 → 按"一个躯干长 = 0.5 米"折成米。离得远的人（小）走同样几个像素，身体走得更远 —— 这是真实距离。
2. 乘 `MIRROR_X`（docs/04 §1 唯一定义处）：观众往自己右边走，身体往屏幕右边走。
3. **组居中**：减掉平均值。相机不动（docs/49 §3 用法 C 仍然否掉），是身体们整体回到中线。
4. **挤开**：相邻两具至少隔 `minGap` 0.8m，夹进 `±maxOffset` 1.3m。
5. 每具身体用临界阻尼弹簧追自己的目标（带 5cm 死区），伴随身体往后站 `backstep` 0.35m —— 交叉的那半秒里一前一后，不互相穿插。

**单人时 `lineup()` 返回 0**：身体永远在中线，逐字等于这一版之前。

### 4.3 镜头

- 一具身体：docs/49 原样（auto / full / upper）。
- 两具以上：**一律全景**，而且画面宽度至少框住整组（`stage.frame` 的包围盒宽度取组宽）。
  理由：中景是"一个坐在笔记本前的人"的正当取景；三个人的中景要么切掉两侧的人，要么不再是中景。
  每具身体的**腿**仍然各自听自己的分类器（`createFramingClassifier` 每人一个，便宜）：坐着的那个人拿站姿的腿，站着的人拿追踪的腿。

### 4.4 进场与退场

不新造任何动画：每具身体各有一个 `createPresence()`，`ENTERING` 长出来、`LEAVING` 缩回去 —— 和一具身体进出场是同一条曲线（docs/05 §5）。
轨迹出生憋的 0.3 秒 + 在场判定的 `enterDelay` 0.4 秒 = 一个人进画约 0.7 秒后身体开始长出来。**从不闪现、从不瞬移**。

## 5 · 性能与预算

### 5.1 共用桶（这一条是整个预算的地基）

`creature.ts` 每个桶 = 部件 × 左右 × 材质。伴随身体用**同一份 genome**，所以它的每一件都落进**已经存在的**桶里：
桶的实例数从 n 变成 N·n，**draw call 一个都不多**。每具身体的颜色是那个桶的 `instanceColor` 里自己那几格。

描边外壳和填充共用 `instanceMatrix`。实例按"主身体在前、伴随身体在后"写，外壳的 `count` 只数主身体那几份 ——
**伴随身体不带描边不花任何东西**，也不需要第二套材质。

几何与材质：部件几何本来就在 `library.ts` 里按 id 缓存、全页一份；伴随身体不解码任何新的 GLB、不建任何新材质。

`instanceColor` 只在 `?people > 1` 时挂上（挂上会让填充材质多一个着色器变体）：单人那条路的管线逐字不变。

### 5.2 面数：公式

```
一具身体最坏那一帧的填充面数 = fill
主身体带描边：× 2（伴随身体在场时可以让位成 × 1）；伴随身体：× 1
N 具： fill × 主身体遍数 + (N − 1) × fill ≤ 250k
```

`fill` 取**被保证的**上界，不取开场那一具的实际面数（`creature/people-budget.ts` 的 `bodyFill`）：

- **忒修斯开着**：借件门（`swap-budget.ts` 的 `makeAdmit`，按 2 遍守）保证任何时刻一具身体最坏那一帧 ≤ 125k。
  按开场那一具算（~98k）会在第三分钟借来一件重的之后越界 —— 那时要么越预算，要么当场溶掉一个人，两个都不行。
- **忒修斯关着**：本物种每一格最重那件的最坏一帧（`worstFrame(own, passes, false)`）。

### 5.3 结论

**[实测：`node --test packages/app/test/people-budget.test.ts` 对 parts.json 里 24 个刚体物种逐个算]**

| | 1 具 | 2 具 | 3 具 |
|---|---|---|---|
| 忒修斯开着（fill ≤ 125k） | 描边照旧，≤ 250k | **描边让位**，250k 正好 | 放不下 → 2 具 |
| 忒修斯关着，最重的物种（wheelleg 稳态 98k） | 描边照旧 | 描边让位 | 放不下 → 2 具 |
| 忒修斯关着，最轻的物种（athlete 24k） | 描边照旧 | 描边照旧 | 描边照旧 |

draw call：任何人数下 = 一具身体（共用桶，`people-budget.test.ts` 第一条）。

**描边让位的代价（要作品负责人知道）**：第二个人进画的那一刻，主身体的描边消失；他走了，描边回来。
现在是**一帧切**（外壳 `count` 从 n 变 0）。§8 第 2 条是把它改成 0.4 秒淡出的计划。另一条路是给多人场景单独一个更高的面数预算 —— 那是作品负责人的决定，不是这条线的。

**第三具身体**要伴随身体的低面数 LOD：`meshoptimizer` 的 simplifier 已经在依赖里（`node_modules/meshoptimizer/meshopt_simplifier.js`），
按部件 id 简化一次、缓存、全部伴随身体共用。r = 0.4 时 125k + 2 × 50k = 225k；但 LOD 几何是另一组桶（+18 draw），主身体又必须不带描边。§8 第 1 条。

### 5.4 调速器

阶梯末尾加一级 `people`（第 7 级）：**只留主身体**，伴随身体走溶解。

- 为什么放在最后：放下一个人的身体是这张阶梯上观众最看得出来的一件事；而前面几级（后期、像素比）对 GPU 的减负比一具不带描边的身体大。
- 为什么不"降低伴随身体的细节"：没有 LOD 之前，身体没有"少一点"可降；有了 LOD 之后，这一级改成"伴随身体换 LOD"，插在「后期」之前（§8 第 1 条）。
- 单人时这一级是 no-op（`governor-wire` 的登记表照旧逐个核对开关存在）。

### 5.5 推理节拍

推理频率照旧由调速器第 3 级管（30 → 15Hz）。多人**不单独降频**：一次 `detectForVideo` 本来就同时读所有人，降频是所有人一起慢。
§1.2 的表如果显示三人档在一个人时也明显更贵，默认值就该留在 1（§6.3），而不是给多人档单独打折。

## 6 · UI / UX

### 6.1 读数：只报主身体，不加"人数"

`ui/readout.ts` 的文件头：「**只装测量，不装作品的决定**」。人数是一个测量，但**台上身体的数量已经在说它** ——
第二具身体长出来就是那一行字。再写一个「人数 2」就是 docs/23 §S4 说的冗余提示（作品负责人不喜欢），也是 P21 说的第二个会漂的仪表。
五行数（置信 / 关节 / 推理 / 动能 / 舒展）都是主身体的：它们回答"它此刻从**你**身上读到了什么"，而那个"你"是驱动读数的那个人。

### 6.2 小屏：画全部人，主身体实线、其余淡

`ui/preview.ts`：每个被跟踪到的人都画骨架 ——

- 主身体：原来那条 0.92 白线，一个像素都不变；
- 有身体的其余人：同一条线，0.5 透明度；
- 被看见了但**没有身体**的人（超过上限、海报）：0.2 透明度的细线。

小屏的职责是说实话（「它有没有看见我」）：第四个人确实被看见了，只是没有身体 —— 骨架很淡，就是这件事的全部表达。不加字。

### 6.3 控件与默认值

- `?people=1|2|3`；控件条「取景」那一组多一项「人数」· 快捷键 N。热切，不重载（worker 在两帧之间重建图）。
- **网页默认 1、现场默认 1**（`PEOPLE.defaultCap` / `defaultCapKiosk`）。理由按顺序：
  1. §1.2：开着多人档而画面里只有一个人，每帧多一次检测器。网页观众 **绝大多数**是笔记本前的一个人。
  2. 网页观众身后路过的人会拿到一具身体 —— 在一个人的桌面上，那读作"它认错了人"，不是"它认出了你们"。
  3. 现场：装置的首要观众是站在站位线上的**一个**人（docs/49 §5.1）；多人是策展决定，`?kiosk=1&people=2` 一个参数就开。
  4. §10 的实测如果显示两人档在一个人时代价可以忽略，第 3 条改成现场默认 2 —— 那一行实测是这个默认值唯一的依据。
