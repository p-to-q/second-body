# SEE-ME SEE-U · PRD

> 作品名 **SEE-ME SEE-U**。仓库、根包与 workspace scope 现在同名：`see-me-see-u` / `@smu/*`。
> 唯一仍写作 `second-body` 的是 **Vercel 项目名**，改它会断掉线上地址（`13-DEPLOY.md` §7）。
> 名字命名的是这件作品的结构：机器看见你，你看见一个非人的自己 —— 一个互看的循环。

> 产品定义。`docs/00-PROJECT-BRIEF.md` 是"我们为什么做"，这份是"做成什么样才算做完"。
> 与 `docs/10-SURFACES.md`（什么真的跑通了）配合阅读：那份是状态，这份是目标。

## 1. 一句话

> 你选一个物种，然后它用你的身体活过来。

## 2. 观众的 90 秒

```
      看见          选择            成为             发现              带走
   ─────────  ─────────────  ──────────────  ──────────────  ──────────────
   空场粒子    六至二十个物种   身体跟随你       它变复杂了        一个 seed
   在呼吸      在形态空间里     1:1 等身        它开始用你的      扫码带走
              滚动             镜像            零件长自己
   S1 Attract  S2 Choose      S3-4 Live       S5-6 Evolve     S7 Leave
```

**核心体验是 S4。** S2 是入口，S7 是收尾，两者都不许喧宾夺主。

## 3. 三条产品主张（排他的）

| 主张 | 含义 | 它排除了什么 |
|---|---|---|
| **等身** | 屏幕上的身体是 1:1 的真人尺寸 | 排除了"缩小的角色预览"、排除了多人同屏并列 |
| **因果可见** | 观众必须能说出"我做了 X，它就 Y" | 排除了纯随机的视觉、排除了延迟 > 200ms 的表达 |
| **物种是真的不同** | 换一个条目 = 换一种**形体**，不是换一层皮 | 排除了"同一具人体换涂装"（这是当前最大缺口，见 §7） |

## 4. 范围

### 4.1 必须有（做不完就不算这件作品）
- S1–S4 + S7 全链路，现场连续跑 30 分钟不用人管
- 至少 **3 种真正不同的形体**（不是 3 种涂装）：人形 / 四足 / 团块
- `?demo=1` 真实录制回放兜底（断网、无摄像头、评委演示都靠它）
- 每个场景的边界情况有明确表现，**不白屏、不报错给观众看**（见 `docs/23-SPEC-ui.md`）

### 4.2 应该有
- S5 升档的视听事件、S6 慢回路（现场真跑一次 AI 生成）
- 海报/留念导出
- Web 部署（陌生人能打开）

### 4.3 明确不做
手指/表情 · 训练任何模型 · 账号与后端 · 排行榜/社交 · 逐帧实时 3D 生成

> **多人：以单人为主，兼容多人**（作品负责人 2026-09-14 裁定）。作品的主张、弧线、读数、取景都按**一个观众**设计，
> 默认 `?people=1`。画面里进来第二、三个人时不再只能丢掉他们：`?people=2|3` 给每个人一具同伴身体（共用实例桶、帧预算内），
> 主观众身份稳定、离开时顺位交接、不重置别人的弧线。设计与没做完的部分在 `docs/50-MULTI-PERSON.md`；
> "等身"那条主张对主观众仍然成立，同伴身体按组取景（`docs/50 §5`）。

## 5. 完成的定义

一件作品，不是一个 demo。判据全部是可观察的：

1. 陌生人**无需任何提示**，站上去 5 秒内知道"那是我"。
2. 陌生人能说出**至少一条**因果（"我抬手它就…"）。
3. 三个物种并排给人看，对方能说出它们**形体**上的区别，而不只是颜色。
4. 随手截一张静帧发出去，对方的反应是"这是什么作品"，不是"你在做什么项目"。
5. 连续跑 30 分钟，无人干预，无白屏无报错。
6. 拔掉网线、遮住摄像头，演示照常进行。

## 6. 技术约束（来自现场，不可协商）

| 约束 | 数值 | 为什么 |
|---|---|---|
| 帧率 | 1440p / 60fps | 低于 50 会被读成"卡"，因果感立刻塌 |
| 端到端延迟 | ≤ 200ms（摄像头→画面） | 超过就不像镜子 |
| 实例 / 三角 / draw | ≤64 / ≤250k / ≤40 | `tuning.ts` 的 `BUDGET`，超了 HUD 标红 |
| 首屏（网页版） | < 3 MB | 陌生人不会等 |
| 冷启动 | 打开一个 URL，不敲第二条命令 | 现场没有第二次机会 |

## 7. 当前最大缺口（诚实版）

**所有条目都是同一具人体换皮。** `orb`（球）、`furball`（毛球）、`patrol`（四足）
这三个条目的全部意义就是"不是人形"，而现在它们是穿着相应涂装的人形。
这违反 §3 的第三条主张，也就是说**作品现在还不成立**。

诊断与解法在 `docs/18-BODY-PLANS.md`。落地顺序：

1. `quadruped` 骨架重映射（纯函数，A 档）—— 一次拿到"真的不一样"的第二种形体
2. `mass` 团块（B 档，MarchingCubes res40 实测 2.43ms / 10.4k 三角 / **1 draw**，
   见 `docs/22-RESEARCH-procedural-bodies.md`）—— 拿到最接近原作的表达
3. `monolith` 资产模式 —— 拿回"像某个真实机器人"的剪影辨识度

在这三件做完之前，**再生成多少素材都不解决问题**。

## 8. 两种形态

| | 现场装置 | 公开网页 |
|---|---|---|
| 入口 | `?kiosk=1`，全屏，无鼠标 | 一个 URL |
| 摄像头 | 固定机位、可控灯光、地面贴位置线 | 用户自己的，环境不可控 |
| 首次访问 | 直接进 | **先放 demo 回放**，按钮才请求摄像头 |
| 慢回路 | 开 | 默认关（限流成本） |
| 隐私 | 现场立牌 | 页面上一行 + 不参与开关 |

网页版第一原则：**不要求授权也能看见东西。** 直接弹权限会流失绝大多数人。
