# 41 · 物质语言 —— 让表面也说那句话

> 策展文档。`docs/40-SESSION-ARC.md` 定了**一个人站在作品前的那几分钟里身体怎么离开他**；
> 这一份定的是**那具身体的表面在同一段时间里说什么**。
> 数值在 `packages/core/src/tuning.ts` 的 `MATERIAL` 块（以及 `TOON` 里新增的一条），
> 这里只解释，不复制。

---

## 0 · 它要解决的那一个问题

作品陈述里有四个词：**datafication / morphogenesis · zoe / simulacrum / other**。
`docs/40` 把它们落到了**时间**上（四个乐章），玩法层把它们落到了**动作**上
（跟随 / 回声 / 抵抗 / 朝向）。

**表面上一个字都没有。**

这不是一处遗漏，它正好压在这件作品自己已经裁过的一条规矩上 —— `docs/26 §I`：

> **身份住在表面，照搬外壳就是照搬身份；身份住在拓扑，照搬几何只是修准比例。**

那一条当时是用来判"换真网格算不算越界"的。反过来读同样成立：
**一条不改变表面的弧线，改不动身份。** 三分钟里形在变、拓扑在漂、它转过来看你 ——
而它身上那层东西从第 0 秒到第 180 秒是同一种物质。于是陈述里最锋利的那一半
（「镜像开始脱离镜像」）只能靠墙上的字来承担，而墙上的字不是作品。

---

## 1 · 一条线，四句话

**只有一个输入：`arc ∈ [0,1]`**（整条弧线的进度，`core/arc.ts` 的 `overall`）。
四个乐章不是四套参数，是四条**互相重叠的连续权重**：

```
        0            0.25          0.5           0.75           1
quote   ██████████▁▁▁▁▁▁▁▁                                          I   datafication
grow        ▁▁▁▁████████████▁▁▁▁                                    II  morphogenesis / zoe
diverge              ▁▁▁▁████████████████████                       III simulacrum
other                          ▁▁▁▁▁▁████████████                   IV  other
```

`quote` 用 smoothstep 衰减，`grow` 是**余弦钟**，`diverge` / `other` 是 smoothstep。
用余弦钟而不是高斯：余弦在两端**精确**归零，高斯永远留一条尾巴 ——
那意味着第 IV 乐章还挂着一点第 II 乐章的微光，一条擦不干净的线。

曲线住在 `app/src/stage/look.ts` 的 `arcWeights()`，**灯和表面读的是同一份**。
放在被两边共用的那一侧是这条线最关键的一个工程决定：曲线一旦复制成两份，
它迟早会在中途分叉，而分叉出来的东西正是 `docs/40` 说的"四个开关"。

### 四句话本身

| 乐章 | 陈述里的词 | 表面在说什么 | 它怎么被做出来 |
|---|---|---|---|
| I | **datafication** | 刚被压成信号：一块**被引用**的物质，不是一件被造出来的东西 | 粗糙度拉向 0.94、金属度压掉 → **没有高光**；三个材质角色的明度压向主色 → 摊成一块色块；彩度压掉三成。灯是翻拍台的平光（补光起、轮廓光落） |
| II | **morphogenesis / zoe** | 在长：它开始有**内部** | 粗糙度按角色分开（primary 往粗、accent 往细 —— 被造出来的东西整具一种表面，活的不是）；**自体微光**：这块材质自己的颜色在薄处透一点出来。AO 与粒子抬一点 |
| III | **simulacrum** | 表面身份开始离开你选的那一套颜色 | 次要色 / 点缀色向两侧转开色相（上限 20°），明度差张开。**主色一动不动** |
| IV | **other** | 它有了自己的物质，而且**那条线不再是我们画的** | 金属度起来、粗糙度落到一个确定值（它开始映屋子，而不是被我们的灯描述）；轮廓光起、主光落；**墨色换成它自己的颜色** |

### 为什么第 III 乐章是"把 `core/palette.ts` 反着做一半"

`core/palette.ts` 把三个材质角色向物种主色收敛，治的是「白瓷躯干 + 深蓝灰四肢 =
装错了零件」。这条弧线在后半段把那次收敛**慢慢松开**。

这是有意为之，也是有风险的 —— 松过头就是把当初治好的病请回来。所以：

- **主色是锚点，一路不转色相。** 陈述写的是「与你相似、却并非你」，
  **相似那一半必须留着**；主色一转，这具身体就不再是观众选的那个物种了。
- 色相偏移上限 **20°**（`MATERIAL.hueSplit = 0.055` 圈）。取证图里
  `patrol` 走到 arc=0.95 时是「黄的躯干 + 橄榄绿的肢 + 陶土色的手脚」——
  仍然读作一具身体，但已经不是你在开场挑的那一具。
- 觉得过了就调 `hueSplit`，**不要去改 `PALETTE`**：那一层管的是"一个物种"，
  这一层管的是"第几分钟"，两件事。

## 2 · 硬约束：不许出现第二套颜色/灯光系统

`LookProfile`（`stage/look.ts`）+ 五套场景（`stage/scenes.ts`）是**唯一**的颜色与光。
弧线因此做成和场景**同构**的第三层：

```
主题（它是什么颜色） → 场景（它站在什么地方） → 弧线（这是第几分钟）
   deriveLook()          applyScene()            applyArc()
```

三层都是作用在同一个 `LookProfile` 上的纯函数。`applyArc()` **只缩放已有字段，
一个新字段都没加**（`test/surface.test.ts` 钉住字段数）。好处和当初场景那一层一样：
`lerpLook` 已经按字段类型插值，所以换主题 / 换场景时的交叉淡入是白拿的。

`stage.ts` 里因此有两个 look 而不是一个：`baseLook`（主题→场景，过渡在它上面插值）
和 `look`（再盖上弧线，渲染读它）。合成一个的话，换场景那一刻会把当时的弧线偏移
一起冻进过渡起点再叠一次 —— 第 IV 乐章换场景会突然暗一档，而且不会自己恢复。

**接触阴影一个字都不改。** 那一项是"它站在地上"，全程不许动 ——
一件飘起来的作品不再是屋里的一件东西（`docs/26 §F`）。
**辉光仍然吃 0.45 那条硬顶**：弧线不是抬高它的理由。

## 3 · 描边翻成默认之后，这份设计变了什么

这份设计动笔时，29 个物种里只有「线」走平涂；写到一半，`DEFAULT_SHADING` 翻成了
`toon`（`204b21e`，作品负责人的决定），**于是每一具身体都变成了一张有墨线的平涂画**。

第一反应是"我的粗糙度/金属度全废了"。但停下来读一遍陈述之后，结论反过来了：

> **平涂 + 墨线本身就是第 I 乐章。**

「摄像头把你压成信号」的视觉对应物，不是一个更花哨的表面，是一具**被画出来的**身体 ——
没有高光、没有材质、只有轮廓和几级色阶，一张关于你的**图示**。
描边翻成默认，等于把 datafication 设成了这件作品的**零点**。

所以这条弧线的任务被重新表述了，而且更准：

> **它开场是一张画，然后一点点变成一个东西。**
> Representation → Other，字面意义上的。

这是个**收获**，不是问题。三条连带：

1. **不申请拆轴，也不动例外表。** "描边开着"和"填充平涂"绑在一根轴上是这次的
   前提，不是这次要修的东西。真要拆（有墨线的 PBR），代价是**再来一遍 29 个物种的
   预算实测**，而现在三角形只剩 7% 余量（232,516 / 250,000）—— 那是另一条线的工作，
   不该由一次表面设计顺手花掉。
2. **粗糙度 / 金属度那一半代码留着，而且仍然正确**：`?shading=physical` 和
   例外表都还在，哪个物种将来因为"辨识度恰恰建立在连续高光上"被写进例外表，
   这条弧线在它身上一样成立。平涂路径下这两个数被 `MeshToonNodeMaterial` 忽略，
   **不是 bug，是那条路径没有这两个概念**。
3. **第 IV 乐章多了一句只有平涂才说得出的话**：墨色。
   描边是"这是一张画"的标记 —— 那条线是**我们**替它描的边。走到"他者"的时候，
   让这条线换成**它自己的**颜色（压暗后仍然是线），比让它变细或消失都准：
   线还在（负责人要它普遍在），但它已经属于那个东西，不再属于我们的画法。
   上限 `otherInk = 0.55`，不是 1 —— 全换过去墨就没了，而看不见的线和碎掉的线一样不成立。

## 4 · 预算：这条线一次 draw 都没多

这是这份设计最硬的一条约束，也是几个方案被否掉的直接原因：
`char.line` 的外壳把每具身体从 18 draw 顶到 **36 / 40**，而三角形 232,516 / 250,000。
**没有第二种花法。**

所以整条物质语言只做一件事：**重写已经建好的那几块材质的 uniform。**
颜色 / 粗糙度 / 金属度 / 自发光在 three 里都是 uniform，改值不换管线、不重编译。
不建桶、不加 mesh、不加后期 pass。

实测（`/dev/figure.html`，同 seed 同机位，读页面自己的 HUD）：

| 物种 | arc | draw | 三角 |
|---|---|---|---|
| `patrol` | 关 | 36 | 56,086 |
| `patrol` | 0.00 / 0.35 / 0.62 / 0.95 | 36 | 56,086 |
| `porcelain` | 关 | 36 | 171,844 |
| `xeno` | 关 | 36 | 175,976 |
| `compact` | 关 | 36 | 180,940 |
| `coral` | 关 | 36 | 171,552 |

**四个乐章的读数和"关掉"逐字相同** —— 这条弧线的运行时成本是零次额外提交、
零个额外三角形。桶数由槽位拓扑决定（18），`test/outline-budget.test.ts`
已经在 29 个物种 × tier 1–3 × 8 个 seed 上守着它。

会重编译管线的那几个属性（`flatShading`、`clearcoat` 从 0 变非 0 —— 它们是 define）
**一个都不碰**：管线重编译发生在帧循环里，而帧循环里不许有会卡住的东西（P2/P5）。
自发光是 uniform 不是 define，但"这块材质有没有自发光"是在建材质那一刻定的，
所以现在**永远给一个值，哪怕是黑的** —— 黑色等于什么都没改，却把那条路从第一帧就打开了。

## 5 · 否掉的几条，和为什么

| 方案 | 它想说什么 | 为什么否 |
|---|---|---|
| **第三种着色 `quoted`**（无光照平涂 / 线框 / 扫描线 / 全息） | 第 I 乐章"被引用的数据" | 三条，任何一条单独成立：① `docs/26 §F` 的反面清单 —— 它立刻读作**滤镜**，不再是屋里的一件东西；② 换着色语言要**重建全部材质与桶**（`setShading` 把桶全丢了），那是一次**硬切**，而 `docs/40` 要的是一条连续的线；③ 预算：36/40 上没有第三条路径的位置 |
| **点云 / 粒子化身体表示第 I 乐章** | 同上 | `field`／「场」这个物种**整具就是一片点**（`creature/swarm.ts`）。把它借来当一个乐章的效果，等于把一个物种的身份降级成一段特效 |
| **平滑法线修外壳裂口** | 手脚的墨碎片 | 会把躯干上"形体交叠处墨变厚"一起削平 —— 而那是**有方向的**线，是这套语言要留的东西。验收条件写得很清楚：躯干的轮廓**不许变得更匀**。这是"把它磨平"，不是"把它修好"（详见 §6） |
| **按某个几何标量自动调墨宽** | 同上 | **量过，没有标量分得开**（§6 有实测数字） |
| **`clearcoat` 表达第 II 乐章的"湿/新"** | morphogenesis | `clearcoat` 从 0 变非 0 是一个 **define**，会在帧循环里触发管线重编译。留作规格：哪天材质在建的时候就带一个极小的非零 clearcoat，这条就能零成本打开 |
| **色阶（`TOON.bands`）随弧线张开** | 平涂的身体"长出内部" | 想做，**没做**。色阶贴图是**进程级共享**的一张 3 像素纹理，一具身体改它等于改全场；而且那会把一次纹理上传放进帧循环换一个二阶的收益。留作规格，见 §7 |
| **给观众一条可见的"进度"** | —— | `docs/26 §F` 反面清单 + `docs/40 §5`：进度条把一段经历翻译成一个百分比，而这件作品的题目正是那种翻译的代价 |

## 6 · 墨为什么按槽位分档（手和脚那次修复）

描边翻成全局默认之后，同一个 12mm 外壳被放到 29 个物种上重新看了一遍，
结论分成**两半**，而这两半不是同一件事：

- **躯干 / 四肢 / 头：留着。** 线会变粗、会在形体交叠处叠墨 —— 但它**有方向**，
  起笔收笔都在。那是这套语言要的东西。
- **手和脚：坏了。** 一块白团上挂着几片脱落的黑渣，没有起笔也没有收笔。
  那不是"变粗的线"，是**外壳散架了**。

判据就是这一句：**会变粗的是线，碎成片的是坏的。**

### 为什么是一张按槽位的表，而不是一个自动判的标量

因为量过，**没有标量分得开**。同一具瓷（seed 12345 / tier 2）实测的世界包围球半径
（`/dev/figure.html?probe=ink`）：

| 槽位 | 世界半径 | 墨 |
|---|---|---|
| `joint` | 0.079 – 0.093 m | **干净**（全身最小的件） |
| `clavicle` | 0.111 m | 干净 |
| `hand` | 0.124 m | **碎** |
| `foot` | 0.140 – 0.143 m | **碎** |
| `head` | 0.155 m | 干净 |
| `spine` | 0.345 m | 干净 |

「小」不是原因 —— **最小的关节盖片最干净**。真正的区别是**形状**：
关节是凸的球、肢是管，而手和脚是全身仅有的两个**有分叉、有凹陷**的槽位（指、趾），
12mm 的外壳在那种薄而弯的特征上会自交、翻面，于是散成片。
这一点从"手"和"脚"这两个词就能读出来，从任何一个整件的标量都读不出来。
所以它是一张**看出来的表**（P15），和 `SHADING_OF_THEME` 同一类：
`TOON.outlineSlotScale = { hand: 0.40, foot: 0.40 }`，**其余九个槽位乘 1**。

0.40 是看出来的，两头都试过：**0.60 时手脚上仍有碎片**，
**0.25 时脚上那圈墨细成一根头发丝** —— 而"墨不见了"和"墨碎了"一样不成立。

### 验收：只有手和脚变了

改前 / 改后同机位同 seed 逐像素相减，差异**只落在两处**：
手（y 425–500）和脚（y 650–700），其余**一个像素都没动** ——
所以"躯干的轮廓没有因此变得更匀"不是一句自我评价，是一张差图。
取证与数字见 §8。

成本：外壳材质按线宽缓存，目前全场两档 = **两条 GPU 管线**。
外壳 mesh 的数量没变，**draw call 一次都没多**（§4 那张表就是改后测的）。

## 7 · 只是规格，还没做的

老实列在一处（`docs/26 §G`：状态标记本身就是诚实，不必在每节末尾再告解一遍）。

1. ~~**弧线还没有人调它。**~~ **已接**（`cca14ab`）：`main.ts:529-530` 每帧把
   `arcState.overall` 交给 `stage.setArc()` 和 `body.setArc?.()`。现场看到的是
   开着的样子，不是关掉的样子。
   这一条留在这里划掉而不是删掉，是因为它错的方向值得记一次：一份规格说
   "还没做"、而东西其实已经做完了，读它的人会去重做一遍，或者更糟 ——
   在现场以为自己看到的是默认态。**过期的谦虚和过期的吹嘘一样是假话。**
2. **色阶随弧线张开**（§5 那一行）。要做的话，先把 `TOON.bands` 从进程级共享
   改成每具身体一份，再谈。
3. **`clearcoat` 的第 II 乐章**：等材质在建的时候就带一个极小的非零 clearcoat。
4. **灯那一半没有取证图。** `applyArc()` 有单元测试（平光 / 轮廓光 / 0.45 硬顶 /
   不碰接触阴影），但 `/dev/figure.html` 自带一副写死的灯、不走 `LookProfile`，
   而 `/dev/stage.html` 没有 `?still=`，无头截不到。**灯那一半的视觉判断是未验证的。**
5. **没有真人看过。** 整条线只在合成 A-pose 上跑过。`docs/26 §E` 那个唯一的问题
   （"陌生人五秒内会不会说那是我"）这条线没有回答过 —— 它动的是第 40 秒之后的事，
   但第 I 乐章的"压平"确实落在那五秒里，**那是最需要被真人否掉一次的地方**。
