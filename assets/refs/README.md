# 参考图 (image-to-3D 的输入)

放法：`assets/refs/<themeId>/*.png|jpg`。
只要某个主题的目录里有图，该主题的所有配方就自动走 **image-to-3D**
（第一张图会被 Rodin 用于材质生成），prompt 退化为方向性引导。

## `_anchor.png` 是自动生成的

如果一个主题**没有**人工参考图，工厂会：

1. 先用 text-to-3D 生成该主题的 `spine.<theme>.a`，并带上 `preview_render=true`，
   Rodin 会额外返回一张官方渲染图；
2. 把这张渲染图存成 `_anchor.png`；
3. 该主题剩下的 19 件全部以这张图作为参考图生成。

好处：**同一主题内的风格一致性由构造保证**，而不是靠 prompt 里的形容词碰运气
（这正是 docs/09 的 U6）。而且整套素材是自洽的，不依赖任何第三方图片。

## 关于放真实产品照片

技术上完全支持：把图丢进 `assets/refs/<theme>/` 就会生效。
但要清楚这意味着什么 —— image-to-3D 的目标就是**还原图里那个物体**。
喂一张某公司机器人的产品照，产出的零件就会是那台机器人的三维复制品，
放进一件公开展出的作品里，这是产品外观的再现，不是"受启发"。

所以默认路径是 `_anchor.png`：**造型语言取材于真实产品，但形体是我们自己的**
（themes.ts 文末的 References 记录了每个主题取材自哪些产品的设计语言）。
要不要放真照片是创作决定，工具这边不拦；只是别在不知情的情况下走到那一步。

自己拍的、自己画的、自己生成的参考图没有这个问题，随便放。
